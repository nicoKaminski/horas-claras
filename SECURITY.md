# Política de seguridad

Horas Claras utiliza autenticación, Supabase y datos de trabajo privados. Cualquier posible problema relacionado con acceso, permisos, sesiones, Row Level Security (RLS) o exposición de datos debe tratarse como sensible.

## Cómo reportar una vulnerabilidad

No publiques vulnerabilidades ni detalles que permitan explotarlas en Issues, Pull Requests u otros espacios públicos.

Usá el [reporte privado de vulnerabilidades de GitHub](https://github.com/nicoKaminski/horas-claras/security/advisories/new) cuando esté disponible para este repositorio. Si no está disponible, escribí a la dirección pública de contacto indicada en el [README](README.md): nicokaminski89@gmail.com.

Incluí, si los conocés:

- un resumen del problema y su posible impacto;
- las partes de la aplicación afectadas y las condiciones necesarias para que ocurra;
- pasos de reproducción seguros, sin acceder ni modificar datos ajenos;
- evidencia saneada que ayude a entender el problema;
- una forma de contactarte para aclaraciones.

No hagas pruebas destructivas ni pruebas que creen, cambien o eliminen datos. No incluyas credenciales, tokens, cookies, datos laborales reales ni otra información privada en el reporte o en sus adjuntos. Si necesitás explicar un caso, usá ejemplos ficticios con `dev` y `compa`.

## Divulgación

Mantené el reporte y los detalles técnicos en privado mientras se analiza el problema. No publiques una prueba de concepto explotable ni información que exponga datos o facilite el abuso.
