# Cómo contribuir

Gracias por ayudar a mejorar Horas Claras. Las propuestas y contribuciones deben respetar el alcance del proyecto y proteger la información privada.

## Issues y propuestas

- Usá Issues para reportar errores o proponer mejoras.
- Si el cambio es importante o afecta varias partes del producto, conversalo en un Issue antes de implementarlo.
- Una propuesta sirve para abrir la discusión; no implica que vaya a aceptarse ni que se convierta en un requisito.
- Los problemas de seguridad no deben publicarse en Issues. Seguí las instrucciones de [SECURITY.md](SECURITY.md).

## Ramas y Pull Requests

El flujo de contribución es:

`rama de trabajo → Pull Request → main`

Creá cada contribución en una rama distinta de `main`. `dev` es la rama habitual de trabajo. `main` se usa para integrar cambios únicamente mediante Pull Request.

En cada Pull Request:

- explicá qué cambia y por qué;
- indicá las validaciones que realizaste y las que quedaron pendientes;
- agregá capturas o evidencia visual cuando el cambio modifique la interfaz;
- revisá que el cambio no exponga información privada ni altere reglas funcionales que no formen parte de la propuesta.

## Seguridad y privacidad

No incluyas secretos, credenciales, tokens, cookies, datos laborales reales ni otra información privada en Issues, Pull Requests, código de ejemplo o capturas. Para reportar una vulnerabilidad, usá el canal privado indicado en [SECURITY.md](SECURITY.md), no un Issue público.
